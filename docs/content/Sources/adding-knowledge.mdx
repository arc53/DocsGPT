# Add Knowledge

**Knowledge** is the content DocsGPT searches and cites when it answers: files you upload, web pages, GitHub repositories, wikis, and content synced from services you connect. When you add a source, DocsGPT parses it, splits it into chunks and embeds them into the vector store. At question time it retrieves the most relevant chunks and passes them to the model with the question. The model itself is not changed.

## Open the Add knowledge dialog

<Steps>
### Open Knowledge

Go to **Settings > Knowledge** and click **Add knowledge**. From a chat, you can also open the composer's **Knowledge** menu and choose **Upload new**.

### Pick a source type

| Option | What it adds |
| --- | --- |
| **Upload File** | Files from your computer, including `.zip` archives. See [Upload files](#upload-files). |
| **Website** | Web pages by their addresses, or a whole site found through its sitemap or its links. See [Add web pages or a website](#add-web-pages-or-a-website). |
| **GitHub** | A public repository, by its URL. Private repositories go through your GitHub connection. |
| **New wiki** | An editable Markdown wiki that agents can read and rewrite. See [Wiki sources](/Sources/Wiki-sources). |
| **Connect your data** | Content synced from a connected service, such as Google Drive, SharePoint, Confluence or Amazon S3. See [Connectors](/Sources/Connectors). This tile shows only when the instance has a connector that syncs. |

### Name the source and add it

Every source needs a **Name**. It is how the source appears on the Knowledge page and in the knowledge pickers. For an upload, the name starts as the first file's name.

**Advanced settings** (not shown for a wiki) holds the chunking and retrieval options for this source. The defaults suit most content; see [Per-source configuration](/Sources/Per-source-configuration) for what each option does.

Click **Add to Knowledge**. The dialog closes, and a panel in the corner shows the upload, parsing and embedding progress. The source appears on the Knowledge page when indexing finishes. If indexing fails, the source's menu offers **Reingest**.
</Steps>

## Upload files

**Upload File** accepts one or more files. Files you pick together become one source.

To upload a folder, drag it onto the upload area or click **Or choose a whole folder** under it. Picking or dropping again adds to the list, and **Remove** takes a file off it. Every supported file inside it is uploaded, and the source keeps the folder's subfolders, the same way a zip archive does. The source is named after the folder unless you type another name. Hidden files and folders, such as `.git`, are left out.

The upload dialog accepts these types:

- **Documents:** `.pdf`, `.docx`, `.doc`, `.docm`, `.odt`, `.rtf`, `.txt`, `.md`, `.rst`, `.html`, `.xhtml`, `.epub`, `.json`
- **Spreadsheets:** `.xlsx`, `.xls`, `.xlsm`, `.xlsb`, `.ods`, `.csv`
- **Presentations:** `.pptx`, `.ppt`, `.pptm`, `.pps`, `.ppsx`, `.ppsm`, `.pot`, `.odp`
- **Images:** `.png`, `.jpg`, `.jpeg`. Their text is read with OCR when OCR is enabled (`OCR_ENABLED`, off by default). `PARSE_IMAGE_REMOTE` instead uploads each image to the hosted `https://llm.arc53.com/doc2md` service, so if images must stay on your servers, use `OCR_ENABLED`. With both off, an image adds no text. See [Document parsing and OCR](/Sources/ocr).
- **Audio:** `.wav`, `.mp3`, `.m4a`, `.ogg`, `.webm`. Audio is transcribed with speech-to-text, and the transcript is indexed.
- **Archives:** `.zip`

<Callout type="info" emoji="ℹ️">
The upload dialog takes files **up to 25 MB each**. It lists larger files, and files of other types, as not added. Uploads through the API are capped by the server instead: `UPLOAD_MAX_FILE_BYTES` (100 MB per file by default), `UPLOAD_MAX_REQUEST_BYTES` (256 MB per request) and, for audio, `STT_MAX_FILE_SIZE_MB` (50 MB).
</Callout>

**Zip archives** are extracted on the server, and every supported file inside is indexed, including archives nested up to three levels deep. Files of other types are skipped. This is also how to upload `.mdx` files, which the dialog doesn't list. The server rejects an upload whose archives expand past `UPLOAD_MAX_ARCHIVE_BYTES` (250 MB), hold more than `UPLOAD_MAX_ARCHIVE_FILES` (10,000) files, or nest deeper than `UPLOAD_MAX_ARCHIVE_DEPTH` (3). The size and file-count limits apply to all the archives in one upload combined. Office and e-book files (`.docx`, `.xlsx`, `.pptx`, `.odt`, `.epub` and similar) are zip containers internally, but DocsGPT parses them as documents and does not unpack them.

Scanned PDFs and images need OCR, which is off by default (`OCR_ENABLED`). See [Document parsing and OCR](/Sources/ocr) for the parser engines and OCR settings. All size and parsing settings are listed in the [settings reference](/Deploying/Settings-Reference).

## Add web pages or a website

**Website** adds pages from the web and keeps each page's address, so answers and the [chat widget](/Extensions/chat-widget#sources-and-citations) link back to the page a passage came from. Under **What to add**, pick one:

- **This page** fetches exactly the addresses you enter. Click **Add another page** to put several pages in one source.
- **Whole site** starts at the address and adds the pages it leads to on the same site.

The **Name** starts as the site's host name; type over it to change it.

### Whole site options

| Option | What it does |
| --- | --- |
| **Page limit** | How many pages to fetch from the site. It starts at 100, which is also the most one source can hold unless an admin changes it. An admin sets the starting value with `WEB_DEFAULT_PAGES` and the most pages per source with `WEB_MAX_PAGES`. |
| **Stay under** | Only fetch addresses that start with this path, such as `/docs`. If the address you enter ends in a folder, such as `https://example.com/docs/`, this starts as that folder. Leave it empty for the whole site. |
| **Find pages** | **Automatic** (the default) reads the site's sitemap and, if the site has none, follows links from the start page. **Sitemap** uses only the sitemap; **Follow links** never reads it. |
| **Sitemap URL** | Shown when **Find pages** is **Sitemap**: a sitemap to read instead of the one the site lists in `robots.txt`. You can also enter a sitemap's address, such as `https://example.com/sitemap.xml`, as the website address. |
| **Include subdomains** | Also fetch pages on other subdomains of the same domain, such as `blog.example.com` for `example.com`. |

DocsGPT looks for a sitemap in the site's `robots.txt`, then at `/sitemap.xml` and `/sitemap_index.xml`. A sitemap that lists other sitemaps is followed down to the pages, and compressed (`.xml.gz`) sitemaps are read. When a sitemap holds more pages than the limit, DocsGPT drops the addresses outside **Stay under**, the other subdomains and the skipped addresses first, then takes pages in the sitemap's own order until it reaches the limit. When a sync stops at the limit, the source's **Settings** say **page limit reached**.

A source holds at most `WEB_MAX_PAGES` pages (100 by default) across everything it fetches, so a sync never has more to fetch than that. Pages added by their address count first, and sites share what is left in the order they were added. **Add pages** is refused when the source would go past the limit.

### What DocsGPT keeps from a page

DocsGPT keeps a page's main content as Markdown: headings, lists, tables and code. It leaves out the navigation, headers, footers, forms and sidebars of links. Images are kept as their alt text. Responses that aren't HTML, and pages with no text, are skipped.

Link addresses inside the page text are dropped by default, because they add text that doesn't help search. If answers should be able to point to the pages a page links to, turn on **Keep links in page text** in the website form, or later in the source's **Settings**. It keeps the addresses of links that sit inside sentences, stores about a quarter more text, and can rank search results slightly lower.

### Keep it up to date

**Keep up to date** sets how often the source is fetched again: **Never**, **Daily**, **Weekly** or **Monthly**. It starts at **Never** for pages and **Weekly** for a whole site. A sync fetches every page again, so the source follows the site as pages are added, changed and removed.

Pages are fetched from the DocsGPT server, not from your browser. Pages behind a sign-in can't be read, and addresses that resolve to private or internal addresses are refused.

### Manage the pages of a website source

**View** on a website source lists its pages by title, with each page's address, size and the time it was fetched. Pages from a whole site are grouped by the folders in their addresses. If you can edit the source:

- **Add pages** fetches more page addresses, or another whole site, into the same source. Pages are fetched right away and are kept in every sync. Adding a whole site rebuilds the source.
- **Refresh page**, in a page's menu, fetches that page again now. If the fetch fails, the page keeps its content.
- **Remove from source** deletes a page's chunks. A page you added by its address leaves the source's list. A page found by crawling a site, or a whole folder, is added to the source's skipped addresses, so later syncs leave it out.

**Settings**, in the source's menu, shows what a website source fetches and what it skips, above its retrieval and chunking settings. There you can remove an address or a site from the list, **Restore** a skipped address, switch **Keep links in page text**, change **Keep up to date**, or click **Sync now**. Changes to the list apply at the next sync.

<Callout type="warning" emoji="⚠️">
A sync replaces a website source's chunks. On a source that is kept up to date, chunks you add or edit by hand are replaced at the next sync.
</Callout>

Sources added with the earlier **Link**, **Crawler** and sitemap options open as website sources. Their pages show titles and addresses after their next sync.

## Add a GitHub repository

Paste a public repository URL, such as `https://github.com/arc53/DocsGPT`. An operator can set `GITHUB_ACCESS_TOKEN` to raise GitHub's rate limit for these public reads. That token is never used for private repositories.

For a private repository, use **Connect GitHub** in the form, or **Pick a repository** if you are already connected. These buttons appear when the GitHub connector is set up on the instance. They hand over to the GitHub connection, which lists your account's repositories. See [GitHub](/Sources/Connectors/github).

## Sync content from connected services

**Connect your data** lists the services on this instance that can sync into Knowledge. Pick one, sign in, then choose which files or folders to sync and how often. You can also start from **Connect a service** on an empty Knowledge page, or from **Settings > Connectors**. Operators must configure each connector first; see [Connectors](/Sources/Connectors).

## Manage your knowledge

Each source on the Knowledge page has a menu. Which items appear depends on the source type and on your access to it:

- **View** opens the source's files and chunks. If you can edit the source, you can edit, add and delete chunks.
- **Sync now** appears for sources that are fetched again: websites, GitHub repositories and connector content. A sync replaces the content, so it can overwrite chunk edits.
- **Settings** opens one dialog for the source. A website source starts with its pages and schedule (see [Manage the pages of a website source](#manage-the-pages-of-a-website-source)); a GitHub or connector source starts with **Keep up to date**, its sync schedule. Then come the retrieval and chunking settings. Retrieval changes apply on the next question. Chunking changes apply only after the source is re-ingested. See [Per-source configuration](/Sources/Per-source-configuration).
- **Test retrieval** runs a question against the source and shows which chunks come back.
- **Convert to wiki** turns the source into editable wiki pages. This can't be undone, and it stops the source's sync schedule: a wiki doesn't sync.
- **Share with team** shares the source with a team. See [Access control](/Deploying/Access-Control).
- **Delete** removes the source and its index.

An open source keeps the same actions in its header: **Test retrieval**, then its main action (**Add file** for an upload, **Add pages** for a website, **Sync now** for a synced source), then the ⋯ menu with the rest. **Delete source** there returns you to the Knowledge page.

To build a knowledge graph over a source, see [GraphRAG](/Sources/GraphRAG).

## Use knowledge in chats and agents

- **In a chat without an agent**, click **Knowledge** in the composer and select one or more sources. Answers draw on the chunks retrieved from them and cite them. The menu's footer has **Go to Knowledge**, **Connect more** (the connectors that sync into Knowledge) and **Upload new**.
- **In an agent**, pick sources in the agent builder's **Knowledge** field (**Select knowledge**). Knowledge is optional: without it, the agent answers from the model and its tools. When you chat with an agent, the composer hides the Knowledge button because the agent uses its own. See [Agents](/Agents/basics).

**Attach** in the composer is different. It adds a file to the current conversation only. To reuse a file across chats and agents, add it to Knowledge instead.
