# Using the Web App

This page covers the everyday parts of the DocsGPT web app that aren't specific to agents, knowledge or tools.

## The sidebar

The sidebar holds:

- **New Chat**: start a conversation. A chat without an agent uses the model you pick in the chat box, the prompt you picked for chats (see [Prompts](/Agents/prompts#pick-the-prompt-for-your-chats)) and the default chat tools.
- **Activity**: what runs now, what waits for you and what runs next, with your schedules and monitors. The row counts what is running and shows a dot while something needs you. See [Activity](/Using/activity).
- **Agents**: your pinned agents. With fewer than three pinned, your most recently used published agents fill the list up to three. Click one to chat with it. Hover over it to **Pin agent** or **Unpin agent**. The grid button next to the **Agents** heading opens **Manage Agents**, the agent library. With no pinned or published agents, a **Manage Agents** row takes the list's place.
- **Chats**: your conversations, newest first. Each has a menu with **Rename**, **Share** (see [Sharing conversations](/Using/sharing)) and **Delete**, and can show one [status mark](/Using/activity#status-marks-on-sidebar-chats): working, waiting for your approval, failed, unread or watching.
- **Settings**, grouped into **Personal** (**General**, **Access Tokens**), **Workspace** (**Knowledge**, **Connectors**, **Tools**, **Prompts**, **Custom Models**, **Teams**) and **Monitoring** (**Analytics**, **Insights** while the operator has insights on, **Logs**). Admins also get **Admin**.

## Search your conversations

Press **Ctrl+K** (**Cmd+K** on macOS), or use the search button in the sidebar, to open **Search conversations**. It matches conversation names and the text of your questions and the answers, and shows a snippet of the match. Pick a result to open that conversation.

## The agent library

Open **Manage Agents** to see your agents in tabs:

| Tab | Holds |
| --- | --- |
| **All** | Every tab's agents on one page. |
| **Templates** | Agents provided by DocsGPT, seeded by your operator (see [Seeding premade agents](/Agents/basics#seeding-premade-agents-from-yaml)). |
| **My agents** | Agents you created, published or imported, and your folders. |
| **Team** | Agents your teammates shared with you (see [Teams and sharing](/Using/teams-and-sharing)). |
| **Discovered** | Public agents you opened through a link. **Remove** takes one off the list. |

**Search...** filters the agents by name and description. Each agent card has a menu with the actions your access allows: **Logs**, **Edit** (or **View**), **Export as YAML**, **Share with team**, **Pin agent**, **Move to folder** and **Delete**.

### Use a template

A template can't be edited directly. Choose **Duplicate** from its menu to get your own published copy in **My agents**, with a new API key. Tools you don't have access to are left off the copy, so check its tools before you use it.

### Organize agents in folders

Agent folders look and work like [Knowledge folders](/Sources/adding-knowledge#organize-knowledge-in-folders). They show as tiles at the top of **My agents**, each with how many agents and folders it holds, above the agents in no folder.

1. Choose **New folder**, type a **Folder name** and choose **Create**. Folders nest up to three levels deep; inside a third-level folder, **New folder** is unavailable.
2. To file an agent, choose **Move to folder** from its menu. In the **Move "…"** dialog, type in **Search folders…** to find a folder at any level, or click a folder's arrow to see the folders inside it. The agent's current folder is marked **Current**. Pick **My agents** (no folder) to take it out of its folder, or **New folder** to create one from the dialog, then choose **Move**.
3. Click a folder to open it. The trail, such as **My agents › Customer-facing**, takes you back up, and a line under it counts what the folder holds. Inside, you see only that folder's folders and agents; **Team** and **Discovered** are hidden. **New agent** there files the new agent in the folder, and an empty folder offers **New agent**.
4. The folder's **⋯** menu, on its tile or at the end of the trail, has **Rename**, **Move to folder** and **Delete**. Deleting a folder moves its agents and folders up to the folder it was in, or out to **My agents**; it doesn't delete them.

Searching from the top lists folders whose name matches first, then every matching agent with the folder it's in. Inside a folder, **Search in …** covers that folder and the folders in it.

Folders are personal. Anyone who can see an agent can file it in their own folders, including an agent a teammate shared with you, and filing it changes nothing for the owner or anyone else. A shared agent you file still shows under **Team** too.

Through the API, agent folders are `/api/folders` with `type=agent`, and `POST /api/folders/items` files many agents at once; see [Folders through the API](/Sources/adding-knowledge#folders-through-the-api). The older `/api/agents/folders` routes, including `move_agent` and `bulk_move`, still work. An agent's `folder_id` in `GET /api/get_agents` and `GET /api/get_agent` is your own filing.

### Pin agents

**Pin agent**, from an agent's card menu or the sidebar, keeps the agent at the top of the sidebar's **Agents** list. Pins are per user, so pinning a shared agent changes only your sidebar.

## Import an agent from YAML

To bring in an agent exported from another instance (**Export as YAML**):

1. In **Manage Agents**, choose **Import**.
2. Drop a `.yaml` or `.yml` file on the dialog, or click to choose one, then choose **Review**.
3. The dialog shows whether the file creates a new agent or updates one you already have, and how it will match **Sources**, **Tools** and **Models** to your account. For a source that isn't found, pick one of yours or **Leave unattached**. A Knowledge folder the agent used is listed under **Sources** and matched to one of your own folders by its path, then by its name: it reads, for example, **Carriers: using your folder**, or **Carriers: you have no folder with this name**. For a folder with no match, pick one of your folders or **Leave unattached**; the problems the import would leave are listed first, under **Check before you import:**. For a tool or custom model that needs a secret, enter it, or leave it blank to skip that item.
4. Choose **Import**.

A new agent is imported as a draft. Re-importing a file updates the matching agent and keeps its current status, so a published agent stays live. If something was skipped, the dialog lists it before **Continue to agent** opens the agent.

<Callout type="warning">
Importing a file that has no workflow over an existing workflow agent permanently deletes that agent's workflow, its run history and its artifacts. The review step warns you when this will happen.
</Callout>

For the same import over the API, see [Agent portability](/API/agent-api#agent-portability-export--import).

## General settings

**Settings → General** has:

- **Theme**: **Light** or **Dark**. Until you pick one, the app follows your system setting.
- **Language**: the language of menus and labels: English, Deutsch, Español, Français, 日本語, 普通话, 繁體中文（臺灣） or Русский.
- **Delete all conversations**: permanently deletes every conversation in your account.

Theme and language are saved in your browser, so set them again on another browser or device. The prompt for chats without an agent is picked on **Settings → Prompts** and saved to your account; see [Prompts](/Agents/prompts).

## Default tools in chats without an agent

Chats without an agent get a few built-in tools by default, such as memory, reading a web page and scheduling (your operator sets the list with `DEFAULT_CHAT_TOOLS`). To stop one of them being used in your chats, open **Settings → Tools** and turn off its switch; it's under **Included**. Tools you add yourself have the same switch. See [The Tools page](/Tools/basics#the-tools-page).
