# Activity

**Activity**, right under **New Chat** in the sidebar, shows the work DocsGPT does for you outside the chat you have open. The row shows how many things are running, and a dot while something needs you: amber for an approval or a connection to reconnect, red when something failed.

Activity has these pages:

- **Now**: what runs this minute, what waits for you and what runs next.
- **Schedules**: every schedule across your agents (see [Agent Schedules](/Agents/schedules#all-your-schedules-in-activity)).
- **Monitors**: what the assistant is watching for you (see [Monitors](/Tools/monitors#managing-monitors)).

## Now

**Now** updates live and has four parts:

- **Needs you** lists tool calls waiting for your approval (with when the approval expires), schedules that paused themselves after failing several runs in a row, and connections whose sign-in expired. **Review** opens the chat with the approval, **Resume** restarts the schedule and **Reconnect** opens **Settings → Connectors**. The section is hidden while nothing needs you.
- **Running** lists chat answers being written in any of your chats, background jobs (code execution and other long tool calls), scheduled runs, webhook runs, workflow runs and knowledge being indexed, with how long each has run and its progress when there is one. Filter it with **All**, **Chats**, **Automations** and **Knowledge**.
- **Up next** lists the schedules due in the next 24 hours. An hourly schedule shows once, with how many times it runs.
- **Watching** lists your active monitors.

The cards on top count what is running, what needs you, the runs due in the next 24 hours, and the scheduled runs and background jobs that failed in the last 24 hours.

### Stop a running answer

**Stop** on a chat answer ends it from the Now page, as if you had stopped it in the chat: the answer keeps what it wrote so far. The answer stops within a few seconds, or, when it is inside a long tool call, as soon as that call returns. **Cancel** on a background job asks the job to stop, as the **Cancel** on its card in the chat does.

<Callout type="info">
Stopping an answer from another page needs Redis, which every DocsGPT install runs. Without it, **Stop** reports that it couldn't stop the answer; stop it in the chat instead.
</Callout>

## Status marks on sidebar chats

A chat in the sidebar shows at most one mark, the most urgent one. Hover over it to see every state the chat is in.

| Mark | Means | Goes away when |
| --- | --- | --- |
| Red dot | Something failed while you were away: the last answer, or a background job | You open the chat |
| Amber dot | A tool call waits for your approval | You approve or deny it, or it expires after 30 minutes |
| Spinner | The chat is writing an answer or runs a background job | It finishes |
| Purple dot | Something new arrived while you were away | You open the chat |
| Hollow ring | The chat has an active [monitor](/Tools/monitors) | The monitor ends or is paused |

## Over the API

`GET /api/activity/now` returns what the Now page shows, and `POST /api/messages/<message_id>/cancel` stops a running answer. Both take a session token only; [personal access tokens](/API/personal-access-tokens) can't call them, because they span every chat and agent of the account. The [REST API reference](/API/reference) describes them.
